## 비밀값은 쉽게 흩어진다

API 키, DB 비밀번호, 토큰 같은 값은 코드가 커질수록 사방으로 퍼진다. 개발자 노트북마다 평문 `.env` 파일이 생기고, 키 값은 메신저로 공유되고, CI 설정과 클라우드 콘솔에도 같은 값이 복사된다.

이렇게 되면 세 가지가 어려워진다. 누가 어떤 값을 가지고 있는지 모르고, 키 하나를 바꾸면 어디까지 바꿔야 하는지 추적할 수 없고, 유출돼도 알아차리기 어렵다. 이 문제를 흔히 시크릿 흩어짐(secret sprawl)이라고 부른다.

## 시크릿 관리 서비스가 하는 일

Infisical, Doppler 같은 서비스는 비밀값을 한곳으로 모으고, 필요한 곳에 안전하게 주입해 주는 것을 목표로 한다. 대표적인 기능은 다음과 같다.

- **중앙 저장소**: 모든 시크릿을 한 곳에서 관리한다. `.env` 돌려쓰기를 끝낸다.
- **주입(inject)**: 로컬 실행, CI/CD 파이프라인, 클라우드 런타임에 값을 자동으로 넣는다. 디스크에 평문을 남기지 않고 메모리로만 주입할 수도 있다.
- **환경 분리**: dev / stage / prod 별로 값을 따로 둔다.
- **접근 권한 제어(RBAC)**: "주니어는 prod 시크릿을 볼 수 없다" 같은 통제를 건다.
- **감사 로그**: 누가 언제 어떤 값을 보거나 바꿨는지 기록한다.
- **버전·로테이션**: 값을 주기적으로 교체하고, 이전 버전으로 되돌린다.

CLI 경험은 Vercel과 비슷하다. 권한 있는 계정으로 로그인한 뒤, 한 줄로 환경 값을 당겨오거나 그대로 주입해 실행한다.

```bash
infisical login
infisical run -- python manage.py runserver   # 값을 주입해 실행
infisical export --format=dotenv > .env        # .env 로 내려받기
```

## Infisical과 Doppler

둘은 결이 조금 다르다.

- **Infisical**: 오픈소스(MIT)라 직접 셀프호스팅하면 인프라 비용만 든다. 클라우드도 소규모는 무료 티어가 있다.
- **Doppler**: SaaS 전용이고 개발자 경험이 좋다는 평이 많다. 대신 무료 티어 인원을 넘으면 좌석당 과금이라 팀 규모에 따라 비용이 빠르게 오른다.

작은 팀이 "무료 또는 저비용"을 원하면 셀프호스팅이 가능한 Infisical 쪽이 선택지가 넓다.

## 그런데 우리는 도입하지 않는다

이미 클라우드의 시크릿 매니저를 환경별로 쓰고 있고 계정 권한도 거기서 관리하고 있다면, 위 기능의 대부분(중앙 저장, 환경 분리, 권한 제어, 감사 로그, 버전·로테이션)은 이미 갖춰진 셈이다. 같은 역할의 서비스를 한 겹 더 얹는 것은 중복이다.

남는 차이는 로컬에서 값을 당겨오는 개발자 편의 정도인데, 이건 기존 시크릿 매니저 CLI를 감싸는 짧은 스크립트로 메울 수 있다. 그래서 멀티클라우드 이전이나 비개발자용 UI 같은 분명한 필요가 생기기 전까지는, 새 서비스를 도입하지 않는 편이 단순하다.
